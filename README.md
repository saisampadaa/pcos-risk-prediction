# Explainable AI-Based PCOS Risk Prediction System

An end-to-end data science capstone: dataset audit → EDA → preprocessing → model
training/tuning → held-out validation → SHAP explainability → an AI explanation
agent → a FastAPI backend and Streamlit demo app.

**This is an academic research and decision-support prototype. It does not
diagnose PCOS, replace a healthcare professional, or provide medical treatment.**

## The headline finding (Phase 1)

Before any modeling, the dataset audit found that `PCOS_lifestyle.csv` (2,000 rows)
is not an independent sample - it's a jittered, repeated expansion of the same
541 patients in `PCOS_clinical_2.xlsx`. Training on one and "externally
validating" on the other would leak patient identity across the split. The
project was redesigned around a **patient-level split** (432 train / 109
held-out patients) instead of a file-level split - see
`notebooks/01_dataset_audit.ipynb` for the full evidence and
`src/data_splitting.py` for the fix. Every later phase's data pools trace back
to this decision.

## Project structure

```
data/            raw, interim (patient-split pools), processed
notebooks/       01 dataset audit -> 08 SHAP analysis, each executed end-to-end
src/             reusable pipeline code (loading, preprocessing, training,
                 tuning, evaluation, validation, SHAP, the AI agent)
models/          frozen pipeline (pcos_risk_pipeline.joblib) + metadata
reports/         figures and result tables generated by the notebooks
app/             FastAPI backend (main.py, services.py, schemas.py) +
                 Streamlit demo (streamlit_app.py)
```

## Final model

Logistic Regression (L1, tuned) - chosen over Random Forest/Gradient Boosting
for the highest recall among candidates (this project's stated priority: a
missed PCOS case is costlier than a false alarm), full interpretability for
SHAP, and the smallest train/validation overfitting gap. See
`notebooks/06_tuning.ipynb` for the full comparison and rationale, and
`models/model_metadata.json` for the frozen model's metrics and known
limitations.

## Running locally

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# Streamlit demo
streamlit run app/streamlit_app.py

# FastAPI backend (separate terminal)
uvicorn app.main:app --reload --port 8000
```

Copy `.env.example` to `.env` and set `GROQ_API_KEY` to enable the AI
plain-language explanation (Phase 9). Without it, the app automatically falls
back to a deterministic rule-based explanation template - the app still works,
just without the LLM.

## Notebooks (run in order for the full story)

1. `01_dataset_audit.ipynb` - the patient-overlap finding and feature mapping
2. `02_eda.ipynb` - 12 visualizations, training-partition only
3. `03_preprocessing.ipynb` - the reproducible pipeline, incl. the BMI-consistency fix
4. `04_modeling.ipynb` - 6 baseline models, grouped cross-validation
5. `05_evaluation.ipynb` - full metric suite, ROC/PR/calibration curves
6. `06_tuning.ipynb` - hyperparameter search, final model selection, freezing the pipeline
7. `07_external_validation.ipynb` - held-out patient validation + dataset-shift check
8. `08_shap_analysis.ipynb` - global + individual SHAP explanations

## Known limitations

- The held-out validation set (Phase 7) is from the **same source population**
  as the training data, not a genuinely independent cohort - a real external
  dataset was not available for this project.
- Follicle count and cycle regularity - the model's strongest predictors - are
  themselves Rotterdam diagnostic-criterion features, not independently
  discovered risk factors.
- Calibration is imperfect (see `notebooks/06_tuning.ipynb`).
- Risk-category thresholds (Lower / Moderate / Elevated) are documented,
  arbitrary demo choices, not clinically validated cutoffs.

Full details in `models/model_metadata.json` and each notebook's own
limitations discussion.
